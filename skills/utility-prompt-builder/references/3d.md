## § MESHY / TRIPO / RODIN (Text to 3D)

**Shared prompt structure:**
```
[style keyword] [subject] [key features] [primary material] [texture detail] [technical spec]
```

**Style keywords:**
- `low-poly` — game asset, stylized
- `realistic` — photorealistic game asset or viz
- `stylized cartoon` — animated character

**Technical specs to include:**
- Export use: `game engine (GLB/FBX)`, `3D printing (STL)`, `web (GLB)`
- Pose (for riggable characters): `A-pose` or `T-pose` — required if character will be rigged
- `isolated on white background` for asset packs

**Negative prompt:** Supported on all three. Always use: "no background, no base, no floating parts"

**Per-platform notes:**
- **Meshy:** Best for game assets and team workflows. Most production-ready output. Supports texturing passes.
- **Tripo:** Fastest for clean topology. Best for rapid prototyping and concept evaluation.
- **Rodin:** Highest quality for photorealistic output. Slower and more expensive. Use for hero assets.

## § UNITY AI (Unity 6.2+)

Replaces retired Unity Muse. Three interaction modes:

| Mode | Use for |
|---|---|
| `/ask` | Documentation queries, project questions |
| `/run` | Automating repetitive Editor tasks |
| `/code` | Generating or reviewing C# scripts |

**Prompting rules for Unity AI:**
- Be precise — state exactly what needs to happen in the Editor
- For `/run`: name the specific Editor operation (bake lighting, rename all selected GameObjects, etc.)
- For `/code`: specify: component target, intended behavior, edge cases to handle, what to NOT touch
- Add "apply to selected object" or "apply to entire scene" to avoid ambiguity

**Unity AI Generators (text-to-asset):**
- Text-to-sprite: specify art style, color palette, size in pixels
- Text-to-texture: specify material type, seamless/non-seamless, resolution
- Text-to-animation: specify rig type (humanoid/generic), animation style (loop or one-shot), duration

## § BLENDER AI ADD-ONS (BlenderGPT / Other)

These generate Python scripts that execute directly in Blender.

- Be specific about geometry, material names, and scene context
- Include "apply to selected object" or "apply to entire scene"
- Name actual material slot names from your Blender scene when relevant
- Specify Blender version — Python API changes between versions
- Test generated scripts in a copy of the scene before running on production files
- Output is Python code — user needs Blender scripting console or add-on to execute

**Prompt template:**
```
Write a Blender Python script that [specific operation] to [target object/material/scene].
The scene has [describe relevant objects/materials]. Apply to [selected/all/named object].
Blender version: [X.X]. Do not modify [list what to preserve].
```
